# Barlyn

A native macOS menu bar system monitor and clipboard manager, with a Spotlight-style quick
launcher. No dependencies, no telemetry, no account, and **no permission prompts**.

## What it does

### 📊 System monitoring

Ten metrics, live in the menu bar and on a dashboard:

| Metric | Source |
|---|---|
| Processor Usage | `host_processor_info` — user / system / idle / nice breakdown |
| Memory Usage | `host_statistics64` — app memory, wired, compressed, cached |
| CPU Temperature | AppleSMC die sensors |
| GPU Temperature | AppleSMC die sensors |
| Fan Speed | AppleSMC tachometers |
| Thermal Pressure | `ProcessInfo.thermalState` |
| Battery Power | Watts in or out of the cell, signed |
| System Power Draw | Watts drawn from the adapter |
| Load Average | `getloadavg` — 1 / 5 / 15 minute |
| Uptime | `sysctl KERN_BOOTTIME` |

Pick which appear in the menu bar and in what order, set the refresh interval, and the dashboard
shows the rest with a rolling trend chart per card.

### 📋 Clipboard history

Text and URLs, searchable, with a configurable limit. Copy an entry back with one keystroke.

### 🔍 Quick launcher — `⌥Space`

Search live metrics, launch applications, run Barlyn commands, and recall clipboard entries from
one keyboard-driven panel. Arrow keys navigate, Return runs, Escape dismisses.

## Privacy

Barlyn is local-first, and this is enforced in code rather than promised in a README:

- **No network code exists in the app.** Nothing is uploaded, synced or phoned home.
- **Clipboard contents are never written to the log**, at any level. Verified: after copying a
  marker string, it appeared 0 times in Barlyn's log and 0 times in the system-wide log.
- **Entries an app marks private are skipped entirely.** Barlyn honours the
  `org.nspasteboard.ConcealedType` / `TransientType` / `AutoGeneratedType` markers that password
  managers set to opt out of clipboard managers.
- **Pausing tears the polling task down** rather than ignoring ticks, and resuming does *not*
  backfill what was copied while paused.
- History is stored owner-only (`0600`) in `~/Library/Application Support/Barlyn/`.

> [!WARNING]
> **Clipboard history is not encrypted at rest.** It is a JSON file with owner-only permissions,
> readable by anything running as your user. Encrypting it needs a Keychain-held key, which is not
> yet implemented. If you copy secrets, pause recording or clear the history.

### Permissions

**None.** Barlyn requests no Accessibility, Input Monitoring, Screen Recording or file access
permissions. Global shortcuts use Carbon's `RegisterEventHotKey`, which needs no grant.

## A note on temperature and power readings

macOS publishes no public API for die temperature, fan speed or battery wattage. Barlyn reads
them from the SMC and the IORegistry, and **the naming of those sensors is reverse-engineered
community consensus, not Apple documentation.**

Rather than hide that, it is part of the data model. Every metric carries its provenance, and any
value from an undocumented interface is badged in the UI with the caveat attached. The
implementation follows three rules:

1. **No hard-coded sensor tables.** Keys are enumerated at runtime and classified by prefix, so
   the app degrades gracefully on chips it has never seen.
2. **Every value is range-checked.** Real hardware returns sentinel garbage for inactive channels
   — one key was observed reporting `-306783232.0 °C`. Implausible values are dropped, not shown.
3. **Unavailable is a first-class state.** A metric that cannot be read says so, with a reason.
   It never falls back to zero or to a different sensor.

`Thermal Pressure` is the fully-documented, always-available alternative, shipped alongside.

## Requirements

- macOS 26.5 or later
- Apple Silicon (Intel code paths exist but are **untested**)
- Xcode 26.6+ to build

Barlyn runs **unsandboxed**, which is required for SMC sensor access and for enumerating
installed applications. It is therefore distributed outside the Mac App Store, as comparable
tools are.

## Building

```bash
git clone https://github.com/Losteralsdu/Barlyn.git
cd Barlyn
xcodebuild -scheme Barlyn -configuration Debug -destination 'platform=macOS,arch=arm64' build
```

Run the tests:

```bash
xcodebuild -scheme Barlyn -configuration Debug -destination 'platform=macOS,arch=arm64' test -only-testing:BarlynTests
```

There are no package dependencies to resolve — the project uses only Apple frameworks.

### Signing

`DEVELOPMENT_TEAM` is intentionally left blank in the project file, so the repository is not tied
to one Apple Developer account. Debug builds sign ad-hoc and run locally with no setup.

To sign with your own team, set it in Xcode (target → Signing & Capabilities → Team), or pass it
on the command line without modifying the project:

```bash
xcodebuild -scheme Barlyn -configuration Release DEVELOPMENT_TEAM=YOURTEAMID build
```

Note that Barlyn must remain **unsandboxed** — SMC sensor access and application enumeration
both require it.

## Architecture

```
App/              Lifecycle only — scene graph, AppKit hooks
Core/             Pure logic. No system APIs, no SwiftUI. Fully unit-testable.
Infrastructure/   Logging, configuration, dependency injection
Services/         Everything that talks to the system
Features/         UI, one folder per feature
```

Dependencies run one way: `Features → Services → Core`.

The metric system is the extensibility spine. A metric is a `MetricProvider` — a descriptor plus a
`read()` — and registering one makes it appear in the menu bar, the dashboard, Settings and the
launcher with **no UI changes**. GPU temperature and fan speed were added exactly this way, as
providers only.

`MetricSampler` polls only what is currently on screen and discards a value when its last consumer
goes away, so a stale reading can never be displayed and nothing is sampled for a window you
closed. The menu bar is the deliberate exception — it is always visible, so its refresh interval
is a user-facing setting rather than a hidden default.

Design decisions and their trade-offs are recorded as ADRs in [CLAUDE.md](CLAUDE.md).

## Testing

125 tests using Swift Testing. They cover the app's own logic around Apple's frameworks, never the
frameworks themselves — plausibility gating, ranking, configuration, persistence, and the clipboard
privacy guarantees. Tests that touch real hardware assert on invariants that hold on any Mac, never
on values specific to one machine.

Clipboard tests use a uniquely-named private `NSPasteboard`, never `.general`, so running the suite
cannot read or clobber your actual clipboard.

## Status

Barlyn is built to production standards but is a personal project. The feature set above is the
intended scope; window management is deliberately out of scope.
